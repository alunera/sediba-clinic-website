# SEDIBA WELLNESS — WEBSITE → BOOKING → CRM → AI → BUSINESS MANAGEMENT SYSTEM

## IMPORTANT CONTEXT

There is ALREADY an existing Sediba Wellness website.

Existing website:

https://sediba-aesthetic-upgrade.replit.app/

Services page:

https://sediba-aesthetic-upgrade.replit.app/services

**DO NOT build a completely separate website.**

The existing Sediba Wellness website is the customer-facing front end.

The new system must be integrated into the existing website so that the customer experiences one seamless Sediba Wellness journey.

The goal is:

**Website → Treatment → Booking → Payment → Client Profile → Appointment → Automated Communication → Follow-up → Reviews → Rebooking → Business Reporting**

The booking system should feel like a natural extension of the existing Sediba website.

---

# 1. CORE ARCHITECTURE

Build the system as two connected layers:

## CUSTOMER-FACING LAYER

The existing Sediba Wellness website.

This includes:

* Home
* About
* Services

* Gallery
* Contact
* Booking

## BUSINESS MANAGEMENT LAYER

A secure admin application/dashboard connected to the website database.

This includes:

* Calendar
* Appointments
* Clients
* Payments
* Treatments
* Products
* Inventory
* Expenses
* Revenue
* Reports
* AI receptionist
* Automations
* Reviews
* Settings

The customer should NOT see the admin system.

# 4. BOOKING FLOW

Create the following customer journey:

### STEP 1 — SERVICE

Customer arrives from the website.

Example:

`/services/signature-facial`

Customer clicks:

**BOOK NOW**

---

### STEP 2 — DATE & TIME

Display a clean booking calendar.

Customer selects:

* Date
* Available time

Only show times that are actually available according to the owner's calendar.

Do NOT show unavailable times.

---

### STEP 3 — OPTIONAL ADD-ONS

If the treatment has configured add-ons, show:

**Enhance Your Treatment**

Example:

Main Treatment
R800

Add-on A

* R150

Add-on B

* R200

Customer can select optional add-ons.

The system recalculates the total automatically.

---

### STEP 4 — CLIENT DETAILS

Collect:

* First name
* Last name
* Email
* Mobile number
* WhatsApp number
* Optional notes

For a new client, create a new client profile.

For an existing client, identify the existing client rather than creating a duplicate.

---

### STEP 5 — BOOKING POLICIES

Before payment, clearly display the relevant:

* Cancellation policy
* Rescheduling policy
* Deposit/payment requirement
* Appointment requirements

Require the customer to acknowledge the relevant policy.

---

### STEP 6 — PAYMENT

Sediba Wellness requires **100% payment/deposit to secure an appointment**.

Therefore:

**No successful payment = no confirmed appointment.**

The payment process should:

1. Calculate booking total.
2. Send customer to payment.
3. Process payment.
4. Confirm successful payment.
5. Create confirmed appointment.
6. Create/update client record.
7. Send confirmation.

If payment fails:

* Do not confirm appointment.
* Allow customer to retry.
* Release the temporary slot after a configurable timeout.

# 7. OWNER CALENDAR

The admin dashboard must contain a calendar.

The owner controls:

* Working days
* Working hours
* Breaks
* Days off
* Holidays
* Blocked dates
* Blocked times

The system must NEVER book outside the configured availability.

The owner must be able to:

* Add appointment
* Edit appointment
* Reschedule
* Cancel
* Block time
* Mark completed
* Mark no-show

The AI can suggest available appointments.

The AI cannot override the owner's calendar.

This is a critical requirement because Sediba Wellness is intentionally operating as a solo practice and the owner wants control over her working schedule.

This is extremely important.

Do NOT create separate disconnected systems for:

* Website
* Booking
* CRM
* AI
* Calendar
* Payments

They must all communicate with the same backend/database.

For example:

```text
SERVICE DATABASE
       │
       ├──────── Website
       │
       ├──────── Booking Engine
       │
       └──────── AI Receptionist

CLIENT DATABASE
       │
       ├──────── Website booking
       ├──────── WhatsApp
       ├──────── AI
       └──────── Admin CRM

       │
       ├──────── Website bookings
       ├──────── AI bookings
```

# FINAL PRODUCT VISION

Do not think of this as:

"A booking page."

Think of it as:

**SEDIBA WELLNESS DIGITAL FRONT DESK + CLIENT MANAGEMENT SYSTEM**

The existing website is the front door.

The booking engine is the receptionist.

The AI is the 24/7 assistant.

The CRM is the client memory.

The calendar is the owner's control centre.

The automation engine handles reminders and follow-ups.

The payment system secures bookings.

The reporting system shows how the business is performing.

Everything connects into one system.

The ultimate objective is to allow Sediba Wellness to move away from fragmented third-party tools and operate its core booking, client communication, CRM and business-management functions from one integrated platform. This aligns directly with the decision made in the August 7 meeting to replace disparate software with an all-in-one system integrated into the website.
